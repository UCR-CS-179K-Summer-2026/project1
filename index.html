System Architecture

Sprint 1 is a four-stage pipeline: a Scanner tokenizes raw text, a Parser consumes tokens and builds a tree of polymorphic JSONValue nodes, a JSONL reader drives the parser one line at a time and answers path queries against the resulting tree, and a thin driver (demo.cpp) wires it together for the CLI.

A .jsonl file flows in on the left: readJsonlFile() reads it one line at a time, hands each line to a fresh Parser, and the parser pulls tokens from a Scanner lazily as it recurses through the grammar. Each line becomes an owned JSONValuePtr tree; lookup() then walks that tree to answer a path query, and formatResult() turns the answer (or an error) into printable text.

Classes & Polymorphism

JSONValue is an abstract base class with one pure-virtual method, getType(). Six concrete subclasses each represent exactly one JSON type and store only the data that type needs — no unused fields, no tagged union. The parser never knows which concrete type it's building next; it just returns a JSONValuePtr (a unique_ptr<JSONValue>), and every caller downstream — lookup(), formatValue() — works through the base-class interface and dispatches to the right subclass at runtime via virtual calls (getType()) or a checked static_cast once the type is known.

JSONValue  (abstract)
virtual ~JSONValue(); virtual ValueType getType() const = 0;
▲▲▲▲▲▲
JSONNullno payload
JSONBooleanbool value_
JSONNumberdouble value_
JSONStringstring value_
JSONArrayvector<JSONValuePtr> items_
JSONObjectvector<pair<string, JSONValuePtr>> entries_

Ownership is move-only: a JSONValue tree can't be copied, only moved, which is why the parser builds it with make_unique<...> and std::move at every step. Code that needs to look inside a tree it doesn't own (like lookup()) takes a const JSONValue&/const JSONValue* instead of copying it. JSONObject stores its entries as a vector<pair<...>> rather than a map, which keeps insertion order and avoids the log-time lookup overhead of a tree-based map for the typically-small objects this format has — lookup() does a linear scan by key.

Alternative considered: the repo's history shows an earlier pass that replaced this hierarchy with std::variant (a tagged union) and then reverted back to polymorphism. A variant avoids heap allocation per node and needs no virtual dispatch, but every consumer has to std::visit or std::get against all six alternatives by hand, and the object/array cases still need vector/heap storage internally anyway. Polymorphism keeps each type's logic (formatting, type checks) local to its own class and makes adding a new JSON extension type a one-class change instead of touching every visit call site — worth re-evaluating in a later sprint once real performance numbers exist.

Module Interfaces

Scanner (Jules)

Turns raw text into one Token at a time, on demand, rather than tokenizing the whole input up front.

enum class TokenType : uint8_t {
    Boolean, Colon, Comma, End, LBrace, LBracket,
    Null, Number, RBrace, RBracket, String
};

struct Token {
    TokenType type;
    string_view value;  // view into the original buffer, no copy
};

class Scanner {
public:
    Scanner(std::string_view json);
    Token scan();  // advances and returns the next token
};

Parser & data model (Jules)

Recursive-descent parser: one parse() call per JSON value, recursing for nested objects/arrays.

enum class ValueType : uint8_t { Array, Boolean, Null, Number, Object, String };

class JSONValue {
public:
    virtual ~JSONValue() = default;
    virtual ValueType getType() const = 0;
    bool isNull() const; bool isBool() const; bool isNumber() const;
    bool isString() const; bool isObject() const; bool isArray() const;
};
using JSONValuePtr = unique_ptr<JSONValue>;

class Parser {
public:
    Parser(std::string_view json);
    JSONValuePtr parse();
};

Edge Case Handling

CaseBehavior
File not found / can't open Throws std::runtime_error with a suggestion (check path, permissions, working directory).
Blank line in .jsonl Stored as JSONNull — keeps records[i] aligned with line i.
Malformed line Warning printed to stderr with the line number, record stored as JSONNull (same alignment reasoning), rest of the file keeps parsing.
Unterminated string / bad token in scanner Scanner::scan() throws runtime_error ("Unterminated string" / "Invalid JSON input"), caught per-line by readJsonlFile().
Wrong token where a key/colon/comma/brace was expected Parser::parse() throws a specific runtime_error ("Expected string key in object", etc.) instead of reading garbage.
Missing field / bad index in lookup() Returns LookupResult{ok: false, error: "..."} instead of crashing (e.g. "field 'x' not found", "index 9 out of range").
Indexing into a non-array, or field lookup on a non-object lookup() checks isArray()/isObject() first and returns a typed error instead of a bad static_cast.

Algorithms & Optimizations

Recursive-descent parsing

Parser::parse() mirrors the JSON grammar directly: one function, one switch on the current token type, recursing into itself for nested object/array values. No lookahead beyond a single token is needed.

Lazy, single-token scanning

Scanner::scan() is pulled one token at a time by the parser instead of tokenizing the whole input into a vector up front. Memory used by tokenization stays O(1) regardless of input size — it doesn't grow with how much of the file has been scanned.

Zero-copy tokens

Token::value is a string_view into the original buffer — scanning a string or number allocates nothing. A copy only happens once, when the parser commits to building a JSONString (or an object key) and needs an owned std::string.

Move-only tree, no deep copies

The whole JSONValue tree is built and threaded through unique_ptrs (JSONValuePtr). Sub-trees are std::moved into their parent container as they're built, so no node is ever copied.

Per-line streaming over the file

readJsonlFile() reads with std::getline one line at a time and parses each line independently, rather than loading the whole .jsonl file into memory before parsing anything. Peak memory is bounded by the largest single record, not the whole file — directly serving the "least RAM possible" goal from the Sprint 1 plan.

Not yet optimized: lookup() does a linear scan over an object's entries for every field access, and each line still gets its own Parser/Scanner instance. Both are fine at Sprint 1 scale and are candidates to revisit once there's a real large-file benchmark to measure against.
